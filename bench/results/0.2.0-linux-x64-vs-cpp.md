# serialport-rs 0.2.0 vs patched C++ — Linux x64

32-byte PTY round trips on Linux x64, Node 26.8.2, with five alternating trials per implementation. Values below are medians of the individual trials' Promise-continuation percentiles.

| Workload | Implementation | Median | p95 | p99 |
| --- | --- | --- | --- | --- |
| Continuous | serialport-rs 0.2.0 | 48.96 µs | 73.42 µs | 114.40 µs |
| Continuous | Patched C++ 13.1.0 | 89.39 µs | 125.21 µs | 202.52 µs |
| 1 ms between exchanges | serialport-rs 0.2.0 | 142.59 µs | 221.33 µs | 303.17 µs |
| 1 ms between exchanges | Patched C++ 13.1.0 | 173.48 µs | 268.96 µs | 392.88 µs |

Continuous trials collected 10,000 samples after 2,000 warmups. Spaced trials collected 1,000 samples after 100 warmups; the gap was excluded from measured latency. Both implementations used the same echo helper and verified every returned payload.

The host exposed four AMD EPYC 9634 vCPUs. Processes were restricted to CPUs 0–2 with nice level 18 and idle I/O priority. Rust used 1.98.1 with fat LTO; the C++ binding used its release build and `@serialport/stream` 13.0.0. The comparison used [DragonWork/bindings-cpp at 23ca033](https://github.com/DragonWork/bindings-cpp/commit/23ca033cf68fbc1bda2837b03bfdaf77bde70ff3), including its Node 26 callback-scope fix.

These measurements describe the host software path through a pseudo-terminal, not UART wire speed or performance on every machine. [Individual trials, environment and binary fingerprints](0.2.0-linux-x64-vs-cpp.json).
